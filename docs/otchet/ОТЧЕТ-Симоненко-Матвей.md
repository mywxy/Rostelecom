## Введение

Цель итогового проекта — закрепить на практике разработку смарт-контрактов на Solidity, их тестирование, интеграцию с веб-интерфейсом и организацию полного цикла создания децентрализованного приложения (DApp).

В рамках работы реализовано DApp **«TODO-лист на блокчейне»**: пользователь может добавлять задачи и отмечать их выполненными; данные хранятся в смарт-контракте `TodoList`, интерфейс построен на **Scaffold-ETH 2** (Next.js, Wagmi, RainbowKit), взаимодействие с сетью — через **MetaMask** и локальную сеть **Hardhat**.

**Исполнитель:** Симоненко Матвей (индивидуальный проект).

**Стек:** Solidity 0.8.30, Hardhat, TypeScript, Scaffold-ETH 2, MetaMask.

## Постановка задачи и обоснование выбора решения

### Постановка задачи

Необходимо разработать DApp, удовлетворяющее требованиям курса:

- смарт-контракт с функциями чтения и записи, событием и проверками `require`;
- unit-тесты (write, event, негативный сценарий);
- фронтенд с чтением данных, формой записи, MetaMask и отображением статуса транзакции;
- ручное тестирование с подтверждающими скриншотами.

### Выбор темы

Выбрана тема из категории «Учёт и регистрация данных»: **TODO-лист с добавлением задач и отметкой выполнения**.

**Обоснование:**

1. Понятная предметная область — легко показать работу read/write функций на примерах.
2. Тема полностью покрывает требования задания без избыточной сложности.
3. На базе Scaffold-ETH 2 можно быстро получить рабочий UI и интеграцию с кошельком.
4. Возможность продемонстрировать события `TaskAdded` / `TaskToggled` и проверку прав (только автор меняет статус задачи).

## Проектирование и реализация DApp-приложения

### Архитектура

DApp состоит из трёх частей:

1. **Смарт-контракт** `TodoList.sol` — хранение массива задач в блокчейне.
2. **Backend развёртывания** — Hardhat, скрипт `00_deploy_todo_list.ts`.
3. **Фронтенд** — Next.js-приложение с двумя страницами:
   - `/` — **чтение** (`getTaskCount`, `getTask`);
   - `/tasks` — **запись** (`addTask`, `toggleDone`).

Связь фронтенда и контракта — через хуки `useScaffoldReadContract` и `useScaffoldWriteContract`; адрес и ABI подставляются из `deployedContracts.ts` после деплоя.

### Смарт-контракт TodoList

Структура задачи:

```solidity
struct Task {
    string text;
    bool done;
    address author;
}
```

| Тип | Функция | Назначение |
|-----|---------|------------|
| view | `getTaskCount()` | Количество задач |
| view | `getTask(uint256 taskId)` | Текст, статус, автор |
| write | `addTask(string text)` | Добавить задачу |
| write | `toggleDone(uint256 taskId)` | Переключить «выполнено» |
| event | `TaskAdded` | При добавлении |
| event | `TaskToggled` | При смене статуса |

**Проверки безопасности (`require`):**

- нельзя добавить задачу с пустым текстом;
- нельзя обратиться к несуществующему `taskId`;
- только `author` задачи может вызвать `toggleDone`.

Локальный адрес после деплоя (Hardhat): `0x5FbDB2315678afecb367f032d93F642f64180aa3` (может измениться при новом деплое).

### Фронтенд

Компонент `TodoListApp` реализует:

- отображение списка задач с адресом автора;
- форму добавления с индикацией «Транзакция…» (`isPending` / `isMining`);
- уведомления об успехе и ошибке (`notification`);
- кнопку **Faucet** для получения тестовых ETH в локальной сети.

**MetaMask:** пользователь подключает кошелёк к `localhost:3000`, выбирает сеть **Hardhat** (Chain ID 31337, RPC `http://127.0.0.1:8545`).

### Автоматические тесты (Hardhat)

Выполнена команда `yarn test` в каталоге `todo-dapp`. Реализованы тесты:

| Тест | Проверяемое требование |
|------|------------------------|
| Добавление задачи + `TaskAdded` | write-функция и event |
| `revert` на пустой текст | `require` |
| `toggleDone` + `TaskToggled` | write и event |
| `revert` при toggle чужой задачи / несуществующего id | `require` |

### Ручное тестирование интерфейса

Сценарий в браузере Google Chrome:

1. Запуск `yarn chain`, `yarn deploy`, `yarn start`.
2. Подключение MetaMask к сети Hardhat.
3. Получение ETH через Faucet на сайте.
4. Страница «Запись» — добавление задачи, подтверждение в MetaMask.
5. Страница «Чтение» — отображение добавленной задачи.
6. Отметка задачи кнопкой «Готово».

| № | Действие | Результат |
|---|----------|-----------|
| 1 | Открыт `/`, кошелёк не подключён | Отображается интерфейс чтения, предупреждение о подключении |
| 2 | Connect Wallet, сеть Hardhat | Кошелёк подключён, баланс пополнен через Faucet |
| 3 | `/tasks` — ввод текста, «Добавить» | Транзакция подтверждена, уведомление об успехе |
| 4 | `/` — просмотр списка | `Всего задач: 1`, текст задачи отображается |
| 5 | «Готово» на своей задаче | Статус «Выполнено», зачёркнутый текст |

## Заключение

В ходе проекта освоен полный цикл разработки DApp: проектирование и реализация смарт-контракта `TodoList`, написание автоматических тестов, развёртывание в локальной сети, создание веб-интерфейса с разделением страниц чтения и записи, интеграция с MetaMask.

Поставленные в задании требования выполнены: реализованы view/write функции, события, проверки `require`, тесты трёх типов, фронтенд на Scaffold-ETH 2 с отображением статуса транзакций, проведено ручное тестирование.

**Ограничения:** приложение ориентировано на локальную сеть Hardhat; для работы в тестовой сети (Sepolia) потребуется отдельный деплой и настройка RPC.
